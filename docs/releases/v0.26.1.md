# SafeTerm v0.26.1

Fix service-group validation in `termctl check` and `termctl apply`.

## Service group checks

Resources with `service.units` now check each declared unit in order. Previously
the host check read only the singular `service.unit`, passing an empty name to
systemctl for a group. Depending on systemd's version, this could either fail
with `Failed to mangle name: Invalid argument` or fail to validate group members.

Single-service resources continue to use `service.unit`. A resource must specify
exactly one of `unit` or a nonempty `units` array. No configuration migration is
needed for correctly defined groups.

Errors identify the resource file, unit or zero-based `units` index, exact unit
name and load-state failure. For example:

```text
resources.d/ali-stack.json: service: units[1] "api.service": LoadState="not-found"; expected loaded (unit may be missing or masked)
```

Checking load state does not start, stop, enable or restart application services.
Group execution order, action grants and audit behavior are unchanged.

## Update

Download and extract the package matching your architecture. From the normal
Linux administrator shell, run:

```sh
sudo termctl update /path/to/safeterm-offline-amd64
sudo termctl check
```

Use the arm64 package on arm64 hosts. Existing administrator definitions,
identities and managed application files are preserved. Finish or roll back any
pending network trial before updating. If you changed resource definitions,
apply them separately with `sudo termctl apply` after the check passes.

For a fresh installation, run `sudo ./install.sh` in the extracted package.

## Validation

Regression tests cover single units, ordered groups, invalid and duplicate unit
names, missing or masked members and systemctl errors. Both check and apply
paths verify every member. The disposable systemd test checks a valid group,
adds an intentionally missing member, requires rejection naming that exact
member, restores the group and exercises ordered start/status/restart/stop.
Release publication is gated on full verification, deployment/SSH end-to-end,
fresh systemd installation and isolated live Netplan tests.
