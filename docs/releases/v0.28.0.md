# SafeTerm v0.28.0

Group administrator settings by purpose under one `/etc/safeterm` root, and
automatically migrate the v0.27 configuration layout during package updates.

## Administrator layout

```text
/etc/safeterm/
  access/
    ssh/                 SSH identities and host key
    console/             Console identities
    roles.d/             Role definitions
    policies.d/          Exact role-to-operation permissions
  commands/
    operations.d/        Command definitions
    executables.d/       Approved binary paths and hashes
    profiles.d/          Runner isolation and resource limits
  resources.d/           Application configuration, services and logs
  network/policy.json    Editable interfaces and network roles
  trust/                 Trusted catalog public key
  docs/                  Detailed administrator and network guides
  README.md              Layout and everyday workflow
```

The `termctl check`, `termctl apply` and `termctl user` commands retain their
existing syntax. Runtime services read the grouped paths. Generated state stays
under `/var/lib/safeterm/generated`, and application files keep their registered
native paths.

## Update from v0.27

Extract the matching amd64 or arm64 package and run from a Linux administrator
shell:

```sh
sudo termctl update /path/to/safeterm-offline-amd64
sudo termctl check
```

The installer checks old/new path conflicts before changing the host. After
taking the installation snapshot and stopping consumers, it renames existing
administrator inputs into the grouped directories. File contents, ownership,
permissions and ACLs are retained; existing users and the SSH host key survive.
Package rollback restores the previous tree and matching binaries together.
Do not move these directories manually before updating. Finish or roll back a
pending network trial first.

This migration covers the v0.27 administrator source layout. Older layouts with
compiled catalogs directly under `/etc/safeterm` remain unsupported; the installer
refuses them without importing or deleting those definitions.

## Network policy and cleanup

The network policy moves from `network.json` to `network/policy.json`. Its empty
default interface allowlist still permits no edits. Policy denial messages now
name the interface and policy path and explain that the editor must be reopened
after the Linux administrator changes the allowlist.

Production packages no longer ship unused demo seed files. Successful updates
remove empty `/etc/safeterm-managed` profile directories. Existing data, symlinks
and unknown entries are retained and reported for administrator review.

## Validation

Local verification includes build, vet, unit, end-to-end, adversarial security and
race checks. Migration tests cover preserved files and metadata, repeatability,
read-only preflight, path conflicts and symlinks. The release pipeline additionally
gates publication on real systemd fresh-install/upgrade tests and isolated Netplan
trials, with packages and SHA-256 checksums for amd64 and arm64.
