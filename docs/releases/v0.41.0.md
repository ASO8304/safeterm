# SafeTerm v0.41.0

- Intentional Ctrl+C stops report `Operation stopped.` in production output.
  TCP/UDP probe diagnoses no longer get a redundant generic failure footer;
  execution/audit failures and optional debugging summaries remain visible.
- Capture accepts `execute capture host IP port NUMBER protocol PROTOCOL` with
  the existing host-or-port requirement and signed validation. Legacy named
  assignments remain accepted for scripts.
- `?` still provides contextual help and preserves input, while help lists and
  Tab omit its entry. `whoami` is replaced by root-level `passwd` (`change_pass`
  alias), with hidden current/new/confirmation prompts.
- Self-service password changes update the authenticated login's credential
  store: Linux/PAM for mapped Console users, the internal Console database for
  legacy users, or the SSH database for SSH users. Passwords, roles and keys in
  the other stores are preserved. SSH password changes take effect without a
  broker restart. The new isolated password service audits changes and never
  grants sudo to operators.
- Route `add` and `edit ID` guide users through validated fields with defaults;
  `set` remains available for further changes. Cancelling preserves prior edits.
  Review with show/diff, then use the existing save/apply/confirm workflow.

Upgrades install and enable `safeterm-password-manager.service`. Individual Linux
Console accounts still require an explicit root-managed mapping and appropriate
OS account restrictions; the installer does not change their login shell,
password, sudo grants or supplementary groups automatically.
