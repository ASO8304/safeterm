# SafeTerm v0.23.2

Add network field types for managed INI and JSON configuration, removing the
need for administrator-written IP regular expressions or repeated port bounds.

| Field type | Accepted values |
|---|---|
| `ipv4` | IPv4 addresses |
| `ipv6` | IPv6 addresses |
| `ip` | Either address family |
| `cidr` | IPv4 or IPv6 address with prefix length |
| `port` | Integer in the inclusive range 1–65535 |

Use lowercase type names in `config.fields`, for example:

```json
[
  { "section": "Cat", "key": "ServerIP", "type": "ipv4", "required": true },
  { "section": "Cat", "key": "ListenPort", "type": "port", "required": true }
]
```

IP validation uses Go's standard `net/netip` package without DNS or network
access. It rejects malformed addresses, hostnames, ports appended to addresses,
surrounding whitespace, zone identifiers, IPv4-mapped IPv6 and the literal `any`.
Valid unspecified addresses and `/0` prefixes are accepted; administrators may
narrow address types using additional length/pattern constraints. Address text
and CIDR host bits are preserved rather than silently canonicalized or masked.

Port fields need no min/max. Optional min/max may narrow the built-in range but
cannot widen it. Zero, negative values, fractions and out-of-range integers fail.
Addresses remain JSON strings; ports use numeric JSON values. INI edits retain
the existing comment, whitespace, BOM and line-ending preservation behavior.

Interactive draft feedback, manager preview/apply, complete-document validation
and the privileged writer share these checks. These are resource configuration
field types; operation request parameter types are unchanged. Existing `string`
and `integer` fields keep their behavior and are not automatically converted.

Inactive templates and installed English Markdown/plain-text resource guides
include the new types. ADR-035 and REQ-031 document semantics and validation.
Tests cover boundaries, invalid inputs, schema constraints, resource compilation,
draft checks, INI byte preservation and JSON numeric/string output.

## Upgrade

Extract the new architecture-specific package and run from a normal Linux shell:

```sh
sudo termctl update /path/to/safeterm-offline-amd64
```

Use the arm64 directory on arm64 hosts. Administrator definitions and identities
are retained. Reconnect Console/SSH sessions after updating. Then change the
desired field types in `/etc/safeterm/resources.d/*.json`, run
`sudo termctl check`, and activate using `sudo termctl apply`.
All existing values in registered fields must satisfy their new type; check
fails on an incompatible value rather than rewriting an application's file.
Changed catalogs require the existing local signer or an offline signature for
the exact candidate. Legacy direct catalog-directory layouts remain unsupported.
