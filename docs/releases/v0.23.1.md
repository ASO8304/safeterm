# SafeTerm v0.23.1

Simplify network diagnostics and terminal completion while preserving typed
validation, signed operations and per-action service permissions.

- `trace` is one operation with `host=`, `port=` and optional `protocol=`.
  At least host or port must be specified; empty and protocol-only requests fail
  before execution. `any` is rejected for all three inputs. Supplied filters
  combine with AND. Remove the default host/port/filtered subcommands and their
  specialized operation IDs.
- `ping` requires only host. Count defaults to 1000 and accepts 1–1000; an
  explicit count of 1100 reports `exceeds maximum 1000`. Normal completion shows
  only `host=` and `count=`, without duplicate aliases/default-value suggestions.
  The explicitly typed `-c` alias remains accepted.
- `execute logs` and `show logs` complete approved log names directly. Explicit
  `source=` syntax remains accepted and completes concrete approved values;
  neither an empty source option nor already-supplied parameters clutter the menu.
- Expand the inactive resource template and installed guides to show status,
  restart, start, stop, enable and disable for an external systemd service.
  Existing exact-unit, per-action authorization remains enforced; the identity
  name `admin` grants no implicit privileges. Regression tests cover all six
  external-service actions, completion and rejection of unauthorized targets.

Conditional argv groups and required-any constraints are signed declarative
operation fields. They retain whole-token substitution and shell-free execution;
runtime requests cannot supply arbitrary BPF expressions. Live output remains
line-buffered. ADR-034 and REQ-030 document the design and acceptance criteria.

Validation: `make verify e2e security`, including the race detector, passed.
Ten generated BPF expressions were also compiled by real tcpdump against an
empty offline PCAP without starting a live capture. Release publication is gated
on privileged boundary tests and real systemd installation/Console tests.

## Upgrade

Download and extract the package for the server architecture, then run from a
normal Linux admin shell:

```sh
sudo termctl update /path/to/safeterm-offline-amd64
```

Use the arm64 directory on arm64 hosts. Administrator source definitions and
identities are preserved. Reconnect existing Console/SSH sessions after updating.
The new packaged defaults apply unless explicitly overridden by site definitions.
If you override trace, ping or policies referencing `trace_host`, `trace_port` or
`trace_filtered`, revise those JSON definitions before upgrading: the three old
operation IDs no longer exist in the defaults. An inconsistent candidate fails
validation rather than silently deleting or rewriting administrator definitions.
Changed catalogs require the existing local signing key or an offline signature
for the exact candidate. Legacy direct catalog-directory layouts remain unsupported.
