# SafeTerm v0.38.0

Identify the configuration blocking a network save and reject invalid route
field values before they enter the draft.

- Gateways must be unicast IP addresses without CIDR prefixes. Entering
  `set gateway 192.168.222.1/24` now rejects the value immediately with
  `set gateway 192.168.222.1` as the correction, retaining the previous value.
- Route destinations validate network CIDR syntax and identify host bits.
  Route interfaces must be editable current names; future persistent names
  receive guidance to use the current name until device activation.
- Save validates the whole cached candidate before sending it to the manager.
  Errors identify the actual invalid route by displayed ID/type/interface and
  explain that existing routes can block unrelated interface or route changes.
  Drafts stay open. Manager-side validation remains independent and uses readable
  route descriptions instead of generated hashes.
- Route show output highlights invalid imported configuration. IP-family
  consistency remains a save-time check so operators can stage changes to both
  destination and gateway. Missing field values receive contextual usage hints.
- Default route protection and save/apply/confirm behavior remain unchanged.

Regression tests reproduce a malformed imported default gateway blocking an
unrelated interface/new-route save, repair it alongside other staged edits,
verify no mutation on rejection and exercise future-name and IP-family checks.
