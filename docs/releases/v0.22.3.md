# SafeTerm v0.22.3

Accept a leading UTF-8 BOM in registered INI files. Previously its bytes before
`[Section]` caused `invalid INI assignment on line 1` during termctl check/apply.
Blank lines and multiple comment lines were already supported.

The parser treats only the initial UTF-8 BOM as a file signature and preserves
it on read/write. Comments, whitespace, LF/CRLF and final-newline state remain
unchanged; only the selected value is replaced. UTF-16/UTF-32 and malformed or
duplicate INI syntax remain unsupported. No manual file conversion is needed.

Regression tests cover a Cat section with blank lines and comments, BOM before
root-level keys, byte-for-byte round trips and edits, and strict rejection cases.
The real systemd installation/Console test now reads and saves a BOM-prefixed
INI through the installed manager/writer and verifies the exact resulting bytes.

Update an existing v0.22.x installation with the extracted release package using
`sudo termctl update /path/to/safeterm-offline-amd64` (or arm64). Then retry
`sudo termctl check` and `sudo termctl apply` for the resource definition.
