# SafeTerm v0.24.1

Register application logs through `resources.d` without overlapping packaged
sample log commands.

- Remove the built-in `log` operation and its `authentication`, `service_A` and
  `system` sources. No log sources are enabled without administrator definitions.
- Stop creating the sample `service_A.log` during installation. Existing log
  files are not deleted.
- Retain the `log-viewer` role, isolated log-reader profile and `tail` binding for
  resource-generated log commands. Completion and per-log authorization remain.
- Update installed Markdown/plain-text guides and document ADR-038.

Define logs in `/etc/safeterm/resources.d/*.json`, using the inactive
`TEMPLATE.json` as a reference. A log-only resource needs no service or config
section. Apply definitions and reconnect, then use:

```text
execute logs RESOURCE_ID LOG_ID
```

## Update

Extract the package for your server architecture and run from the normal Linux
administrator shell:

```sh
sudo termctl update /path/to/safeterm-offline-amd64
```

Use the arm64 package on arm64 hosts. Administrator definitions and identities
are preserved. If you previously copied the old `log` operation into
`operations.d` (often `log.json`), migrate its paths to `resources.d` and
remove/disable that explicit override; otherwise it still registers your custom
command. Run `sudo termctl check` and `sudo termctl apply` after editing inputs.
Application log files must exist and be readable by the isolated log reader.

Local `make verify e2e security` passed, including race checks. Regression tests
cover absence of packaged log registrations and sample file creation, and
resource-only log completion with authorized generated operation IDs. Release
publication is also gated on the real systemd installation/Console smoke test.
