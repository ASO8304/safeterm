# SafeTerm v0.22.0

## Breaking configuration architecture

This release supports only the resources.d architecture. Installers refuse old
configuration layouts before deployment; no automatic migration, import, or
configuration deletion is performed. Back up an existing installation and
re-express its intended resources as JSON definitions on a clean deployment.
Do not use this release as an in-place upgrade of a legacy layout.

- Define independent configuration files, logs and systemd services under
  `/etc/safeterm/resources.d/*.json`; the installed `TEMPLATE.json` is always ignored.
- Validate with `sudo termctl check` and activate with `sudo termctl apply`.
- Compiled runtime data lives under `/var/lib/safeterm/generated`; credentials
  and trust remain under `/etc/safeterm`.
- Old catalog/config mutation commands and legacy source loading are removed.
- Activation rebuilds from verified packaged built-ins and current definitions,
  without importing previously generated operations or registries.
- `termctl apply --rollback` restores the previous completed activation;
  `termctl apply --recover` handles interrupted activation. Package rollback is separate.

## Terminal and security changes

- Contextual SSH/Console configuration editor: `config RESOURCE`, `edit SECTION`,
  `set KEY VALUE`, `diff`, `end`; saves multiple fields atomically.
- Authorization-aware Tab completion and `?` followed by Enter for help.
- INI comments, ownership, ACLs and unrelated text are preserved by the restricted writer.
- Audit owns only `/var/lib/safeterm/audit`, isolated from generated metadata.
- Incomplete activation checkpoints fail instead of falling back to current live data.

## Packages and validation

Download the AMD64 or ARM64 offline archive and its `.sha256` file, verify and
extract the archive, then run `sudo ./install.sh` from its directory. Follow the
updated README and installed configuration guides for resource definitions and signing.

Local `make verify e2e security`, including the race detector, passed.
Both architecture packages were built and their internal checksums verified.
Two root-only integration tests are additionally required by the release workflow.
