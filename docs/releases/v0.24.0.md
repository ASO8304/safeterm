# SafeTerm v0.24.0

Define logical configuration commands and field names in JSON, independently of
the physical file's section and key names. No Go changes are needed to add a
context using existing field types and file formats.

## Logical configuration

Register a physical file once with `config.contexts`. Each context declares a
token-array `path` and named fields with their actual section/key and validation:

```json
{
  "id": "network-options",
  "description": "Shared application settings",
  "config": {
    "path": "/etc/product/options.ini",
    "format": "ini",
    "permissions": {
      "read": ["config-viewer", "config-operator"],
      "edit": ["config-operator"]
    },
    "contexts": [
      {
        "path": ["tunnel"],
        "fields": [
          { "name": "Value_1", "section": "Tunnel", "key": "TCPMSS", "type": "integer", "min": 1, "max": 65535 },
          { "name": "Value_2", "section": "Cat", "key": "Port_2", "type": "port" }
        ]
      }
    ]
  }
}
```

Adapt paths/coordinates and illustrative bounds to the real application. Place
the definition under `/etc/safeterm/resources.d`, then check/apply as usual.
In the restricted terminal:

```text
config tunnel
show
set Value_1 1400
set Value_2 2420
diff
end
```

`name` is the case-sensitive CLI field name. It maps to a real key; it does not
translate values. Help, Tab and show/diff use logical names. Supported types,
allow_empty, secrets, readonly fields and constraints retain their behavior.
The existing Tab completion/list workflow is unchanged. Logical singleton
contexts have direct fields without edit/next; abort/cancel discards a draft.

Multiple contexts may share one registered file with one version/lock authority.
End validates and saves once, retaining unrelated fields, INI comments/layout and
ownership/ACL checks. External file changes reject stale saves. Whole-file
rollback affects every context and its confirmation identifies that scope.
Contexts inherit resource-level roles; they do not introduce field-level RBAC.
Conflicting paths/aliases, invalid coordinates and excessive inputs fail closed.

## CLI changes

- Remove root-level `show`; use `execute COMMAND ?` for operation help. Keep
  `show` inside configuration contexts.
- Rename the packaged `trace` operation to `capture`, retaining typed host/port/
  optional protocol filters and streaming. At least host or port is required.
- Remove packaged nslookup/traceroute operations, executable bindings and their
  installation dependencies. No hidden trace compatibility alias is added.
- Configuration saves never restart/reload services. Source `config.on_change`
  is rejected; use explicit authorized `execute service` actions instead.

The inactive resource template and Markdown/plain-text installed guides use the
new schema. ADR-037 and REQ-033 document the design and acceptance criteria.

## Upgrade and validation

Extract the package for the server architecture and run from a normal Linux shell:

```sh
sudo termctl update /path/to/safeterm-offline-amd64
```

Use the arm64 directory on arm64 hosts. Existing administrator definitions and
identities are retained. Before updating, remove any nonempty `config.on_change`
and revise site operation/policy/executable overrides referring to removed
trace/nslookup/traceroute defaults. Invalid candidates are rejected rather than
silently rewriting administrator input. Changed catalogs require the existing
local signer or an offline signature for the exact candidate.

Existing `config.fields` definitions retain resource/section editing. Do not mix
fields and contexts in one resource. A context-based resource exposes only its
logical paths, not an extra raw resource-ID editing route. Reconnect after
updating or applying definitions. Then run `sudo termctl check` and
`sudo termctl apply` after editing definitions. Legacy direct catalog-directory
layouts remain unsupported.

Local `make verify e2e security` passed, including race checks. Tests cover source
compilation, routing conflicts, metadata copies, authorized discovery, alias
mapping, secret redaction, shared-file preservation, cancellation, stale saves
and authenticated SSH/Console IPC. Publication is gated on a real disposable-VM
systemd/Console PTY test that edits a root-owned multi-context file and verifies
that saves do not restart its service.
