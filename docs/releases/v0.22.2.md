# SafeTerm v0.22.2

Fix Config Manager startup on a fresh resources.d installation. The systemd units
still referenced missing legacy `/etc/safeterm-managed/{application,database,network}`
directories, causing `226/NAMESPACE` before the managers could create their sockets.

All three manager units now have no writable application-file mounts. They retain
`ProtectSystem=strict` and empty capability sets; only the restricted writer can
modify registered files. No dummy directories or broader access grants are needed.
Config resource discovery and Tab completion can now contact the running managers.
An empty resources.d directory naturally has no resource names to complete.

CI and the release pipeline now gate publication on a real disposable-VM systemd
installation. The test starts with an empty registry, verifies all manager sockets,
logs into the actual Console through a PTY, registers an INI resource, uses Tab for
resource/section/key selection, saves a value, and verifies comments, mode and
ownership remain intact. Previous in-process IPC tests did not exercise systemd
mount namespaces; this gate closes that coverage gap.

Update an existing v0.22.x installation using the extracted release package:
`sudo termctl update /path/to/safeterm-offline-amd64` (or arm64), then reconnect.
The v0.22.0 legacy-layout restriction remains in effect.
