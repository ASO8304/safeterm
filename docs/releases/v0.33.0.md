# SafeTerm v0.33.0

Configure routes using IDs without inventing names.

- `show` lists routes by ID; use `edit 1` or `delete 2`. Stored route names and
  generated names stay internal, including in prompts, details and local diffs.
- `add` takes no arguments and opens a new route with an automatically assigned
  editor ID. Set its destination and interface; gateway and metric are optional.
  IDs stay stable until the editor closes and are not reused after deletion.
- Incomplete drafts cannot be saved. An empty new route cannot be silently
  staged by `next`. Deleting the selected route returns to the route list.
- IPv4 and IPv6 default routes cannot be deleted. The DELETION column and detail
  view identify protected routes; delete help/completion offers deletable routes.
  The network manager enforces protection at save and apply, including older
  saved candidates and attempts to change a destination before deleting it.

Example:

```text
config network route
show
add
set destination 192.168.20.0/24
set gateway 192.168.222.1
set interface ip0
set metric 100
show
next
save
```

`save` commits only a candidate. Network activation still requires
`execute network apply` and timed confirmation. Default-route settings remain
editable within policy. No installer applies networking.

Coverage includes ID-only selection, numeric stored-name collisions, automatic
creation and stable IDs, required-field validation, default protection in the
CLI and privileged manager, and rejection of older deletion candidates before
any network trial starts.
