# SafeTerm v0.35.0

Persistent interface naming moves into the configuration editor and uses simple
numbered link files.

```text
config network interface
edit ens37
set name lan1
diff
save
execute network apply
execute network confirm
```

- `set name` stages the future name with other interface settings. Dirty prompts,
  show, diff, next, exit and cancel follow the existing editor semantics.
- Save stores the candidate only. Apply/confirm persists the MAC-bound Netplan
  configuration and the `.link` rule together. No live rename is performed; the
  name takes effect on the next reboot/device activation.
- The old `execute network rename` command returns migration guidance and is
  removed from execute help and completion.
- Existing MAC-matched files are reused without renaming their paths. New files
  start at `/etc/systemd/network/11-persistent-net.link`, then 12, 13 and onward
  through 98, skipping occupied filenames and matching drop-in directories in
  systemd's configuration search paths. MAC-based files from v0.34.0 remain valid.
- Naming candidates retain role/policy, source trust, validation, audit, trial
  timeout, stale-source protection and recovery controls. Fully written naming
  commits survive startup recovery; incomplete recovery after activated naming
  or conflicting external edits requires a Linux administrator.

Tests cover local discard and typed save, combined name/settings candidates,
multiple interface names, conflict rejection, numbered filename allocation,
existing-rule preservation, confirmation, rollback and completed-commit recovery.
