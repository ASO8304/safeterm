# SafeTerm v0.23.0

Configure site-specific roles, operations, executables, runner profiles and policies
alongside resources without editing generated files or rebuilding SafeTerm.
Verified packaged defaults remain available on every installation.

- Define optional JSON overrides under `/etc/safeterm/roles.d`, `operations.d`,
  `executables.d`, `profiles.d`, `policies.d` and `resources.d`. Each directory
  includes an inactive `TEMPLATE.json` and English Markdown/plain-text guidance.
- Inspect packaged definitions with `termctl defaults`, inspect runners with
  `termctl profile`, and inspect approved binaries with `termctl executable`.
  Use `sudo termctl check` and `sudo termctl apply` to validate and activate changes.
- Provision bounded custom runners with separate locked system identities,
  sockets, systemd units and audit identity checks. Packaged profile bases fix
  sandbox behavior and privilege ceilings. Service-control grants remain scoped
  to each runner's approved operations.
- Preserve administrator definitions and custom-role user identities during
  package updates. Activation supports transactional rollback and recovery;
  unchanged offline updates can reuse an exactly matching verified catalog.
- Ship the full site configuration reference with installed configuration docs.
  Explicit executable approvals retain their administrator-specified SHA-256;
  inspection does not silently approve changed binaries.

Validation includes formatting, vet, unit/race tests, deployment and SSH end-to-end
tests, security checks, privileged file-boundary tests, and a real disposable-VM
systemd installation test. The latter exercises Console completion, configuration
editing, custom runner execution, isolated service grants, rollback and updates
that preserve custom-role identities.

## Upgrade

Download and extract the package for your architecture, then run from a normal
Linux shell:

```sh
sudo termctl update /path/to/safeterm-offline-amd64
```

Use the arm64 directory for arm64 hosts. Existing v0.22.x installations use the
supported declarative layout; their administrator definitions are retained.
Legacy direct catalog-directory layouts are still rejected and require explicit
migration. Changed catalogs require local signing or an offline signature for the
exact candidate. See `docs/site-configuration.md` for schemas and security limits.

For a fresh installation, extract the package and run `sudo ./install.sh` inside
its directory. The installer prompts for the initial SafeTerm identity and password.
