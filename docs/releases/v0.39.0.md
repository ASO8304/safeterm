# SafeTerm v0.39.0

- Console supports individual Linux logins mapped to SafeTerm identities and
  roles, without a second password prompt. Existing shared-account login remains
  available during migration; SSH authentication is unchanged.
- Saved network candidates are isolated by identity. Another operator's draft no
  longer prevents saving. Legacy global drafts migrate only for their owner.
- Removed NICs and their routes disappear from active editors while their Netplan
  definitions remain on disk. MAC-bound definitions cannot attach stale settings
  to replacement devices. Reopening after hardware/source changes shows current
  devices and preserves the old candidate until explicitly replaced/discarded.
- Live network status and candidate discard remain available with damaged draft
  or Netplan data. Stale editor saves and stale apply attempts still fail safely.
- `/etc/safeterm/terminal.json` customizes the displayed name and prompt for both
  Console and SSH. Defaults preserve `safeterm::username(context)*> `.
- `exit` asks before discarding affected unsaved edits. Enter, `n`, or Ctrl+C
  cancels navigation and keeps the draft. `next`, `save`, `cancel` and Ctrl+] keep
  their existing purposes.
- Netplan file owner/mode no longer blocks editing. Path/directory, symlink,
  hard-link, regular-file, size and concurrent-change protections remain, as do
  the stricter rules for policies, identity mappings, `.link` rules and state.

## Enable single-login Console access

For an existing individual Linux account, from a Linux maintenance account:

```sh
sudo usermod -a -G safeterm-clients,safeterm-gateway alice
sudo termctl user add console --id alice --os-user alice --roles viewer,netops,config-viewer,config-operator
sudo termctl service restart all
```

Choose appropriate roles. Log out of Linux and log back in, then run `termctl`
without sudo. To enter SafeTerm directly after Linux login, explicitly set the
account's shell to `/usr/local/bin/safeterm-console`. Keep a separate Linux
maintenance account. SafeTerm does not automatically create Linux accounts or
change their passwords, groups, or shells.

Mappings are root-managed in `/etc/safeterm/access/console/linux-users.json`.
Old `os_user` entries in legacy `users.json` remain inactive migration metadata;
they do not silently enable this new authentication mode. Kernel UID/PID, audited
expiring sessions, role verification and mapping revocation protect access.

## Customize presentation

```json
{
  "name": "Acme",
  "prompt": "{brand}::{user}{context}{dirty}> "
}
```

Keep `{user}`, `{context}` and `{dirty}`. Run `sudo termctl check`; open a new
Console process and restart the SSH Broker for new SSH sessions to load settings.
Updates preserve the file and existing Linux-account mappings.

Validation includes the full verification/e2e/security/race suites and disposable
VM tests for Linux-account Console login, editor confirmation, real configuration
services, and isolated Netplan trials.
