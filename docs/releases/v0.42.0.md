# SafeTerm v0.42.0

- Create a complete local Console account with one command:
  `sudo termctl user add console --os-user alice --roles viewer,netops`.
  It asks for the Linux password twice, creates the account with the SafeTerm
  login shell and required groups, saves its role mapping and loads access.
  `--id` is optional and defaults to the Linux username.
- Existing usernames, same-name groups and existing home paths are refused;
  choose an unused name. Existing accounts are never converted or modified.
  Existing Console mappings from earlier releases continue to work.
- Console accounts remain password-locked until services are ready. Failed
  provisioning removes its new mapping and leaves the new account locked.
  Home data is preserved. Provisioning is blocked during a network trial or
  another lifecycle operation. Service reload disconnects active SafeTerm
  sessions, which must reconnect.
- Guided fresh installation now has separate SSH and optional Linux Console
  enrollment steps, each with its own username/password. It no longer copies
  the initial SSH password into a Console identity. Upgrades preserve existing
  users; unattended/no-start installs defer Console creation to termctl.
- Bash/Zsh completion and the administrator guides include `--os-user`.

`termctl user add console --id ID` without `--os-user` retains legacy internal
Console enrollment for the shared `safeterm` entry account. SSH users remain
separate service identities. No sudo access is granted to new Console accounts.
