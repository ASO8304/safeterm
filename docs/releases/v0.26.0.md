# SafeTerm v0.26.0

Simpler ping syntax, a bounded TCP connection test, and clearer network
configuration help. Linux-style Tab completion and contextual `?` remain available.

## Ping and TCP diagnostics

```text
execute ping 192.168.89.1
execute ping 192.168.89.1 -c 5
execute ping -c 5 192.168.89.1
execute telnet 192.168.89.1 443
```

- Ping accepts a literal unicast IPv4 address. The default and hard maximum are
  1000 packets; `-c` accepts 1 through 1000. The `host=` and `count=` CLI forms
  are replaced by positional syntax. The signed internal operation parameters
  remain typed and validated.
- `telnet` tests whether a TCP connection can be established. Its optional port
  defaults to 23. It accepts literal unicast IPv4/IPv6 addresses, sends no
  application data and immediately closes a successful connection. It does not
  provide an interactive Telnet login or terminal.
- The TCP attempt defaults to a five-second timeout. Administrators can configure
  `tcp_probe.timeout_seconds` from 1 to 60 in the signed operation definition.
  The native implementation needs no external Telnet executable or new service.
- `netops` authorizes the shipped TCP test. The operation uses the existing
  network Runner, typed validation, authorization, streaming and audit path.
- Ctrl+C cancels the current operation and returns to SafeTerm. Ctrl+] exits
  the SafeTerm session.

See [the diagnostics guide](../network-diagnostics.md), also installed as
`/etc/safeterm/NETWORK-DIAGNOSTICS.md` and `NETWORK-DIAGNOSTICS.txt`.

## Network configuration usability

- `?` in interface and route contexts now explains each available command and
  field. Tab keeps its existing completion behavior.
- Route-context `show` displays configured routes grouped by interface, or the
  selected route. It no longer dumps unrelated interface settings. Empty/new
  route contexts provide guidance. This shows the Netplan configuration and
  candidate, rather than the live kernel routing table.
- Unsafe Netplan file errors identify the path and rejected metadata condition.
  Trusted ownership, permission, link-count and size checks remain enforced.

## Explicit service configuration

The packaged catalog no longer registers SafeTerm's own services as restricted
terminal commands. Administrators define visible service aliases and allowed
actions in `resources.d`. Linux administrators can still manage SafeTerm itself
with `sudo termctl service ...`.

Existing site definitions are preserved on update. An explicit custom policy
that references a removed packaged service operation must be updated along with
the corresponding resource definition; `termctl check` validates the result.

## Install or update

Extract the downloaded package for your architecture and run:

```sh
sudo ./install.sh
```

For an existing installation, from the normal Linux administrator shell:

```sh
sudo termctl update /path/to/safeterm-offline-amd64
```

Use the arm64 package on arm64 hosts. Existing administrator definitions,
identities and managed application files are preserved. Finish or roll back a
pending network trial before updating. Custom operations remain subject to
catalog validation; the shipped ping limit is also enforced at runtime.

## Validation

Full local verification, deployment/SSH end-to-end, adversarial and race tests
passed. Tests cover ping parsing and hard limits, authorization, native TCP
success/refusal/timeout/cancellation and closing connections without application
data. Release publication also gates on fresh systemd installation and Console
PTY tests, including real TCP success and Ctrl+C cancellation, and real Netplan
trial/confirmation/rollback tests in an isolated Ubuntu guest.
