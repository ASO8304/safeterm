# SafeTerm v0.36.0

Fix editing legacy inline Netplan configurations and keep new NIC definitions
in an existing administrator-owned Netplan file.

- Valid inline Ethernet mappings (`ethernets: { ... }`) no longer fail with
  "flow-style Ethernet mappings are read-only" when saving supported edits.
  Affected source files become readable block YAML on confirmation; comments,
  unknown properties and the existing rollback guarantees are retained.
- New interfaces join an existing eligible `/etc/netplan/*.yaml` source. SafeTerm
  no longer creates a separate `90-safeterm-interfaces.yaml` for new hardware.
  Select an existing basename with `new_interface_file` in network/policy.json,
  or leave it empty to select the unique eligible source automatically.
- Multiple eligible sources require an explicit policy choice. File allowlists,
  source trust, renderer and cloud-init restrictions still apply. Existing
  interface entries continue using their original source files; legacy files
  are neither moved nor deleted automatically.
- Combined edits to existing and new interfaces now apply same-position YAML
  insertions in the correct hierarchy order.
- Interface detail labels have consistent spacing, including Persistent Name.
- Netcat failure status retains the concise diagnosis without nested executor
  errors or pinned descriptor paths. SafeTerm still formats probe summaries;
  UDP silence remains inconclusive.

Regression coverage uses the reported MAC-matched inline YAML and checks editing,
confirmation, exact-byte rollback, source selection, missing/ambiguous targets,
comments, unknown properties, and repeat edits after naming a newly discovered NIC.
