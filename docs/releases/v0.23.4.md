# SafeTerm v0.23.4

Support explicitly empty application settings and make configuration validation
failures actionable. Fix registration checks for administrator-defined logs.

- Add `allow_empty` to resource configuration fields and interactive descriptions.
  A present empty string is accepted when explicitly enabled. A missing key still
  fails with `required: true`; nonempty values retain normal typed validation.
  Definitions without the flag keep their previous behavior. Cross-field rules
  remain authoritative.
- Identify resource ID, managed file path, section/key, field type, required and
  empty flags, and numeric bounds in field-validation failures. Distinguish
  missing keys, blank values and invalid values. Secret values are redacted.
- Preserve an inline comment after an empty INI assignment, including BOM and
  line endings. JSON permitted blanks are empty strings; no implicit zero, false
  or null is substituted.
- Fix the catalog administration helper rejecting its own log read-access probe
  as `unsupported catalog administration executable`. Permit only the exact
  fixed unprivileged reader/test invocation; arbitrary sudo commands, identities
  and arguments remain rejected. Actual failures identify log, path and identity.
- Expand installed guides explaining packaged defaults under
  `/usr/share/safeterm/defaults`, administrator overrides under `/etc/safeterm/*.d`,
  inactive `TEMPLATE.json` files and `termctl defaults` inspection/export.

For an optional IPv4 setting that may be blank:

```json
{
  "section": "Sultan",
  "key": "PATIP",
  "type": "ipv4",
  "required": false,
  "allow_empty": true
}
```

Set `required: true` if the key must exist but its value may still be empty.
The editor does not create missing registered keys. Address types, CIDR, ports
and IP endpoints introduced in v0.23.3 remain supported.

Validation: `make verify e2e security` passed locally, including the race detector.
Regression tests cover the required/empty matrix, all scalar types, draft and
manager operations, byte-preserving INI/JSON blanks, contextual errors and secret
redaction. The disposable systemd test now registers a real log, verifies that
readable access passes and unreadable access fails, and activates the definition.
Release publication remains gated on that real installation/Console test.

## Upgrade

Extract the new architecture-specific package and run from a normal Linux shell:

```sh
sudo termctl update /path/to/safeterm-offline-amd64
```

Use the arm64 directory on arm64 hosts. Existing administrator definitions and
identities are retained; reconnect SSH/Console after updating. Then add
`allow_empty: true` to the intended fields, run `sudo termctl check`, and activate
with `sudo termctl apply`. Do not change log ownership to work around the former
internal helper error. Actual access requirements still apply to registered logs.
Changed catalogs require the existing local signer or an offline signature for
the exact candidate. Legacy direct catalog-directory layouts remain unsupported.
