# SafeTerm v0.29.1

Replace the network interface editor's JSON dump with a compact operator view.

## Readable interface display

Inside `config network interface`, `show` lists interface names, IPv4 DHCP,
addresses and editing access in a sorted table. Multiple addresses occupy
separate rows. Read-only reasons appear below the table, with concise policy
guidance. A `*` marks an interface with unsaved edits.

Use `edit NAME`, then `show` for that interface's addresses, DNS, search domains,
MTU, source filenames and restriction details. Empty values have readable labels.
Policy and legacy-gateway restrictions include administrator next steps.

Interface views omit protocol versions, internal ownership/trial fields and
unrelated route tables. Route configuration keeps its existing scoped table.
Editing access describes permission to edit; it does not indicate live link
state. These views show the editor draft. Leave the editor and use
`execute network status` for live network state.

The display reads the cached draft. It does not contact the network manager,
save a candidate, change policy, write Netplan files or apply networking.

## Update and validation

Update with the matching amd64 or arm64 package using `sudo termctl update
/path/to/safeterm-offline-amd64`, then reconnect. Finish or roll back a pending
network trial first. The administrator layout and command syntax are unchanged.

Tests cover sorted/scoped summaries, multiple addresses, empty values, readable
policy restrictions, staged values, omitted protocol data and absence of
mutations. The systemd Console smoke test exercises the interface summary through
the actual network manager. Standard verification, security, race, SSH, systemd
and isolated Netplan release gates remain in place.
