# SafeTerm v0.43.0

- Persistent interface renames now update the Netplan definition ID as well as
  the MAC-bound `.link` rule. A renamed `ip1` no longer retains a
  `safeterm-<MAC>` key. The live name still changes only on the next reboot or
  device activation.
- Newly configured NICs use their actual interface name as the Netplan key when
  no rename is requested. No generated `safeterm-<MAC>` key is persisted.
- Existing renamed interfaces from older releases repair their ID when edited.
  Repeating `set name ip1` explicitly stages the repair without an address change.
  The prompt, detail view and diff show that staged ID change.
- Removed hardware retains its Netplan configuration until explicitly deleted.
  In `config network interface`, use `show absent`, then `delete NAME`, review
  `diff`, and follow save → apply → confirm. This removes that retained definition
  and its stored routes without deleting a present interface.
- Retained definitions cannot be silently overwritten by renames. Name
  collisions, referenced definitions and restricted sources fail with an
  actionable explanation. Policy and source/hardware conflict checks remain.
- Cleanup and ID changes participate in the existing timed trial, confirmation,
  recovery and rollback transaction. Rollback restores original source bytes.

Example, when removed `ip0` is being replaced by `ens37`:

```text
config network interface
show absent
delete ip0
edit ens37
set name ip0
diff
save
execute network apply
execute network confirm
```

Only delete `ip0` if that retained configuration is no longer needed. If the new
name is `ip1`, the old `ip0` remains until you explicitly delete it. IP settings
from the removed device are not copied onto replacement hardware.
