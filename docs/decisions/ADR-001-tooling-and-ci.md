# ADR-001: زبان پیاده‌سازی، محیط توسعه و CI/CD

## Status
Accepted

## Context
پروژه SafeTerm نیاز به یک محیط توسعه دارد که:
- بتواند دستورات واقعی سیستم لینوکس را اجرا و تست کند
- از همان commit اول، build/test/verify خودکار داشته باشد
- روی یک لپ‌تاپ با منابع محدود (۱۶ گیگ رم، ویندوز) قابل اجرا باشد
- نیازی به سرور اختصاصی یا زیرساخت سنگین برای شروع نداشته باشد

## Decision
- **زبان پیاده‌سازی:** Go — به‌دلیل مناسب بودن برای اجرای process، concurrency،
  کتابخانه استاندارد قوی برای تست، و کامپایل به یک باینری مستقل.
- **محیط توسعه:** WSL2 + Ubuntu روی ویندوز — کرنل لینوکس واقعی، بدون سربار یک VM کامل.
- **CI/CD:** GitHub Actions (ابری) — بدون نیاز به میزبانی GitLab/Runner محلی.
  اجرای پایپلاین روی سرورهای GitHub انجام می‌شود، نه روی لپ‌تاپ توسعه‌دهنده.

## Alternatives Considered
1. **VM کامل (VirtualBox/VMware) + GitLab سلف‌هاستد** — رد شد در فاز M0،
   چون مصرف RAM بالا (حداقل ۶ گیگ فقط برای GitLab) و زمان راه‌اندازی زیاد،
   نسبت به ارزش آن در همین مرحله، توجیه ندارد. این گزینه می‌تواند در آینده
   و به‌عنوان یک ADR جدید، برای یادگیری عمیق‌تر DevOps بازبینی شود.
2. **توسعه مستقیم روی ویندوز (بدون WSL)** — رد شد، چون SafeTerm نهایتاً
   باید دستورات سیستمی لینوکس (مثل tcpdump) را اجرا کند و تست روی محیط
   واقعی لینوکس ضروری است.

## Consequences
- توسعه‌دهنده باید WSL2 و Go را روی محیط لینوکسی نصب کند (نه ویندوز مستقیم).
- CI به اینترنت وابسته است (قابل قبول، چون GitHub Actions است).
- اگر بعداً نیاز به سلف‌هاستد GitLab برای یادگیری DevOps پیدا شد، این ADR
  با یک ADR جدید (مثلاً ADR-010) جایگزین یا تکمیل می‌شود، نه این‌که این
  تصمیم به‌صورت بی‌مستند تغییر کند.
