# ADR-049: Route IDs and default-route deletion protection

Status: Accepted. Supersedes the named-route creation and selection behavior in ADR-048.

## Decision

Use only cached editor IDs for route selection and deletion. `add` takes no
arguments, assigns an ID immediately, and selects an empty route draft. Use
`set destination`, `set interface`, and optional `set gateway` / `set metric`
commands to populate it. Internal route names are generated by the broker and
remain the typed identities sent to the manager. Existing stored names are
preserved internally but no longer accepted as CLI selectors.

Keep display IDs stable for the lifetime of the editor, including after a
deletion or discarded new draft. Reopen `show` after opening a new editor.
An empty draft cannot be saved or silently staged with `next`. Partially filled
drafts may remain staged, but save requires an interface and destination.

Prevent deletion of IPv4 and IPv6 default routes. Surface protection in the
route table and detail view, and exclude protected or read-only routes from
delete completion and contextual choices. Enforce the restriction in typed
modifications and compare against active default-route identities at save and
apply. Changing the destination earlier in a draft or loading a candidate
created by an older release does not bypass deletion protection.

## Consequences

Scripts must use `add` and replace stored-name selectors with IDs from `show`.
Default-route fields remain editable within administrator policy. Save commits
only a candidate; timed apply, confirmation, rollback, ownership and policy
checks retain their existing behavior. No new privileged action or persisted
candidate format is introduced.
